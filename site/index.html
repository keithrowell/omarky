Markdown tools for Omarchy.

A reader that makes a plain text file a pleasure to read, a writer in the spirit of Byword, and the changes between two versions of a document, shown in the column you read in. Native Wayland windows that take their colours from your theme.

Principles

The file is the document. Both apps open the Markdown file as it is on disk and never keep a copy of their own. The writer saves the text exactly as you typed it, and the reader reloads in place when another program changes the file. The Markdown file is the only format, with no database behind it and no export step.

Reading deserves its own app. A preview pane in an editor is a second-class view. OmarkyReader has one job, and everything in it is chosen for reading a document from start to finish: the measure, the type, the outline and the keys.

The desktop decides how it looks. Colours come from the current Omarchy theme and follow it as you switch, light or dark. Code blocks take their colours from the theme's own file. There is no theme picker in either app.

Nothing to configure. One background process per app, one window per file, keys you can read in a sheet with ?. The preferences are the few things that change as you read: the zoom and the recent files.

Versions are people and times. When a document lives in git, its history is "Danny, Friday 23 October" and "me, yesterday", never a commit hash. The reader shows what changed between two of them in the same column.

Editing from the reader stays small. A block or a section at a time, in the writer's editor, over the page. For a document, use the writer.

OmarkyReader

A reading column at a measure of about 68 characters, in the prose font the theme suggests. Headings, lists, quotes, tables, code, images, footnotes, task lists and alerts are set the way a typesetter would set them. The outline follows you through the document and jumps on a click.

omarky read notes/plan.md
omarky read docs/spec.md#window-and-behaviour

Find (Ctrl+F or /) steps through matches across the whole document. Links to other Markdown files open in a new window at their heading; web links open in your browser. Right-click any block to copy its Markdown source. The file is watched, so an edit in another program shows up in place, with the page kept on the same paragraph.

Changes between versions

When the file has check-ins in git, a branching chip joins the header. Pick a version and the window compares the file as it is now with that version: added words on a wash in the theme's green, removed words faded under a strike in its red, a tag in the margin for each paragraph that changed.

omarky read proposal.md --from danny
omarky read proposal.md --from yesterday --to "danny fri"
omarky changes proposal.md

Editing a block

Reading and finding a sentence to fix, press E. The block under the mouse opens in a sheet over the page, in OmarkyWriter's editor, with the blocks before and after it faint around it. Shift+E opens the whole section. Type, then Ctrl+Enter: the file is written and the page reloads under the sheet. Esc closes without writing. The sheet never writes over a change that landed while it was open, and in changes mode a reworded block offers its older wording with one chip.

OmarkyWriter

You type plain Markdown and it looks finished as you write: emphasis leans, code sits in a chip, links read as links, and the marks that make it happen fade back. Heading marks, list markers and quote marks hang in the left margin, so the text keeps one clean edge. The text in the window is always exactly the file's Markdown.

omarky write notes/essay.md
omarky write
omarky write --end journal.md
EnterContinues a list, a numbered list (counting up), a task list or a quote. On an empty item, ends the list.
Tab Shift+TabIndents or outdents a list item.
Ctrl+B Ctrl+I Ctrl+EBold, italic, inline code. Again to remove.
Ctrl+KA link around the selection, cursor in the URL.
Ctrl+1 to Ctrl+6, Ctrl+0Heading level, or back to a paragraph.

Misspelt words get a quiet line once you have moved past them, never while you are typing them; right-click one for suggestions. With no file you get a new untitled document, saved as a draft while you type. Named files save themselves a moment after you stop typing. A file changed by another program is reloaded in place when you have nothing unsaved, and offered as a choice when you do.

Architecture

QML on Quickshell. Both apps are built with the toolkit Omarchy's own shell uses, so they are native Wayland windows with no web view and no Electron. The parser is markdown-it; the blocks are rendered as a flat list, one delegate per block, which is what keeps a 5,000-line document scrolling smoothly.

One library, two thin apps. The renderer, the diff engine, the editor and the chrome live in one library at the root of the repository. Each app is a shell, a window and a command line on top of it. That is how the reader can borrow the writer's editor for one block.

One native module. The writer's live Markdown is painted by a small C++ syntax highlighter on the text document, which also sets line height and the hanging marks. It is built on first run when cmake and the Qt headers are there, and the editor runs plain without it.

Git behind the launcher. The window never runs git. The Ruby command line resolves "danny fri" to a version, reads the two texts, and hands the window two texts and two labels. The diff engine aligns the documents by section and paragraph, then by word, and marks the newer document's runs.

Every design choice is written down in docs/decisions, one numbered record each, from why blocks are a flat list to why layout stays outside the undo history.

Install

With quickshell, ruby, ttf-ia-writer, sonnet and hunspell-en_au installed, and cmake with the Qt 6 headers if you want the writer's native module:

git clone https://github.com/keithrowell/omarky.git ~/.local/src/omarky
~/.local/src/omarky/ops/install

The script links omarky into ~/.local/bin, adds a desktop entry and an icon for each app, and builds the native module when it can. It leaves your default Markdown app alone; to make the reader the default:

xdg-mime default omarky-reader.desktop text/markdown

To update, pull and run the install script again. Press ? in the reader or Ctrl+/ in the writer for every key.
